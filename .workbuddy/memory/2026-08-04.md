## 第四阶段：修复 planet.html 预览报错（es-module-shims 干扰）

- **报错**：预览 `planet.html` 出现 `Failed to resolve module specifier "three". Import Map: "three" matches with "three" but is blocked by a null value`。
- **根因（初判错误）**：初判为 es-module-shims 专属错误，先删除了 es-module-shims。但删后仍报**完全相同**的错，且服务器确认发的是修复版 → 说明不是 es-module-shims，而是**环境（预览面板/浏览器）注入了一个把 `three` 映射到 `null` 的 importmap**，与页面自身的 importmap 叠加，原生解析把 `three` 判成 null。
- **真正根治**：彻底放弃 importmap + 裸模块名，改为**相对路径直接 import**：
  - `planet.html`：`import * as THREE from './assets/vendor/three/three.module.js'`、`import { mergeGeometries } from './assets/vendor/three/addons/utils/BufferGeometryUtils.js'`；删除整个 `<script type="importmap">` 块。
  - `assets/vendor/three/addons/utils/BufferGeometryUtils.js`：内部 `} from 'three'` → `} from '../../three.module.js'`（相对路径，否则它内部的裸导入仍会失败）。
  - 这样完全不用 `three` 裸名，外界注入的 `three→null` 映射失效，问题根绝；cannon.js 仍是 UMD 全局，不受影响。
- **校验**：`node --check` 模块脚本语法通过；planet.html 无 importmap/无裸 `three` 导入；BufferGeometryUtils 内部导入已相对化；两个 vendor 模块经服务器均 200 可达；`mergeGeometries` 在全文件正常使用。
- **缓存坑**：改完 es-module-shims 后用户仍报同样错误——根因是浏览器缓存了旧 planet.html（旧版仍含 es-module-shims）。静态 `http.server` 默认会缓存，普通刷新读缓存。已把后台服务器换成强制 `Cache-Control: no-store` 的版本（脚本 /tmp/nocache_server.py，cwd 设到项目目录），之后刷新永远取最新。经验：**迭代改前端时本地服务器应发 no-store，避免与缓存较劲**。

## 第五阶段：修复 planet.html 灰白屏 / 角色失踪（物理坐标爆炸 → NaN 相机）

- **现象**：场景加载成功但画面灰白一片、人物不出现、C/WASD/鼠标拖拽全失效；临时诊断浮层（`#debug-overlay`）显示 `cam: NaN,NaN,NaN`、`char: 8028.60,-6471.64,16955.66`（距原点约 19000，星球半径 R=25）、`children:43`、`loading:no`。
- **根因**：物理仿真失稳。原代码只靠"速度投影"把角色贴在球面走，但没有**强制把角色坐标锁在星球表面**——径向重力 + 碰撞让径向速度反复累积，角色被甩飞/穿心到几万单位，相机跟随插值得到 NaN，于是只剩天空 Shader 的灰白/雾色，啥也看不见。
- **三道保险（均在 `update(dt)` 内，planet.html）**：
  1. **NaN/越界自动复位**：`update()` 开头检测 `charBody.position` 为 NaN 或 `length()>1e6`，则重置回出生点（SPAWN_LAT 球面）、清零 velocity/angularVelocity（行 2415-2421）。
  2. **强制贴球面**：`world.step(1/60,dt,subSteps)` 之后，把 `charBody.position` 长度强制缩放到 `R+charR`（`pos *= (R+charR)/|pos|`），并扣掉速度在法线方向的径向分量（行 2470-2482）。这是**硬约束**——无论物理怎么炸，每帧后角色都被拉回球面，坐标不可能再飞到 19000。
  3. **相机 NaN 兜底**：相机更新后若 `camera.position` 任一分量为 NaN，立刻用角色位置重算（行 2641-2648），避免 `lerp` 把 NaN 永久传下去。
  - 另：前进向量 `forward` 异常时也重新初始化并正交化（行 2425-2432），防零向量/NaN 导致矩阵失效。
- **校验**：抽取 planet module 脚本 `node --check` 语法通过；临时诊断浮层保留待用户确认"角色在 ±25、相机非 NaN"后再移除。
- **附带修复 cube2048.html（同源隐性 bug）**：发现 `games/cube2048.html` 用的是 `<script type="importmap">` + 裸 `from 'three'` + CDN(unpkg three@0.160.0) + `OrbitControls`。同一个"环境注入 `three→null` importmap"会让它打开即报 `blocked by a null value`。已用同款根治法：
  - 新增 `assets/vendor/three/addons/controls/OrbitControls.js`（从 unpkg 抓 r160，内部 `} from 'three'` → `} from '../../three.module.js'` 相对化），与已内置的 r160 three 匹配。
  - `cube2048.html` 删除 importmap，改为相对导入 `../assets/vendor/three/three.module.js` 与 `../assets/vendor/three/addons/controls/OrbitControls.js`。
  - 校验：cube2048 module `node --check` 通过；全项目 Grep 已无 `from 'three'` / `type="importmap"` / `unpkg.com/three` 残留（仅剩 vendored 的 es-module-shims.js 本身无害）。
- **修正（第 5.1 轮）**：用户硬刷新后角色可见、坐标非 NaN，但角色仍飘在空中（`char` 长度约 40.9，而目标半径 R+charR=25.6），且画面抽搐、数值跳动。
  - **新根因**：我只 clamp 了 `charBody.position`，但 Three.js 渲染和相机都读的是 Cannon 的 `charBody.interpolatedPosition`；`world.step()` 后这个插值状态仍记录着未 clamp 的旧值，导致渲染位置与物理位置打架、画面抖动。
  - **修复**：在 clamp `position` 和径向速度之后，立刻把 `charBody.interpolatedPosition` 和 `charBody.previousPosition` 都 `copy(charBody.position)`，确保渲染/相机与物理完全一致（行 2482-2485 附近）。

## 第六阶段：planet.html 操作逻辑改为 FPS 式（鼠标看视角 + WASD 移动）

- **需求**：鼠标控制相机视角、WASD 负责前后左右移动（类似 FPS），替代原来 A/D 转向 + W/S 前后。
- **实现（planet.html）**：
  - 新增状态：`camPitch`(俯仰角)、`lookActive`(指针锁定中)、`pendingYaw/pendingPitch`(鼠标增量逐帧消费)、`MOUSE_SENS=0.0022`、`PITCH_LIMIT=1.25`。临时向量 `_moveDir/_rightAxis/_lookDir`。
  - **鼠标看视角**：点击画布 `requestPointerLock`（标准 FPS 自由视角，Esc 退出后可点 UI）；另加**拖拽兜底**（`mousedown` 左键 + `mousemove` 也转视角），环境拒绝指针锁定时仍可用。仅 `lookActive || _dragging` 时才消费 `mousemove` 增量。`pendingYaw -= movementX*SENS`(右移→右转)、`pendingPitch -= movementY*SENS`(上移→抬头)。
  - **移动改为相对朝向**：`forward` 仍每帧重正交化（切于球面）。偏航在 `update()` 内消费 `pendingYaw` 绕 `tmpUp` 旋转 `forward`；俯仰累积到 `camPitch`。W/S 沿 `forward`、D/A 沿 `_rightAxis(=forward×up)` 合成 `_moveDir` 再归一化设速度。原 A/D 转向逻辑删除；移动端摇杆 `joyVec.x` 仍作偏航、`joyVec.y` 作前后。
  - **相机含俯仰**：`_lookDir = forward.applyAxisAngle(_rightAxis, camPitch)`（第三人称看向 `charPos+up*eyeUp+_lookDir*10`；第一人称眼位看 `camTarget+_lookDir`）。`forward` 仅水平，角色网格仍直立，俯仰只动相机。
  - 桌面提示文案改为"鼠标 看视角(点击锁定/拖拽)"。
- **校验**：抽取 module `node --check` 通过；服务器 task hIsLHA 在线、字节(134521)与磁盘一致、含 FPS 控制串。

## 第九阶段：第二轮体验/设计优化（用户再次要求"再看一下还能优化什么"）

复用无头体检脚本 `/tmp/audit_all.mjs`（Edge + puppeteer-core，13 页：index/games/projects + 10 个游戏；每页测 1440×900 与 375×667 双视口，抓 console/pageerror/requestfailed、横向溢出元素、<40px 触摸目标、meta 四项）。本轮回填并修复了 3 个**真实功能缺陷** + 7 项 meta 打磨。

### 1. 修复 prism.html Service Worker 404（真实运行时错误）
- 现象：prism 控制台报 `A bad HTTP response code (404) was received when fetching the script`（2 次）。
- 根因：prism 调 `GameUtils.registerSW()` 但**漏写** `document.documentElement.setAttribute('data-sw-root','../')`，而 `registerSW()` 默认相对 games/ 注册 → 请求 `games/sw.js` → 404。其余 9 个游戏页都写了 `../`，只有 prism 漏了。
- 修复两处：
  - `prism.html`：补 `data-sw-root="../"` 后再 `registerSW()`（带注释说明子目录必须声明）。
  - `assets/js/game-utils.js`：`registerSW()` 改为**自纠错**——未声明 `data-sw-root` 时按 `location.pathname` 是否含 `/games/` 自动推断 `../` 或 `''`（即便部署到 GitHub Pages 子路径也正确）。这样彻底消除"漏写属性 → 静默 404"这一类 bug。
  - 顺手删掉 game-utils.js 里一处**死重复** `registerSW()` 定义（同一对象字面量里两处同名，后者静默覆盖前者，属误导性的死代码），合并进 §16。

### 2. 修复 gravity.html 移动端横向溢出（手机上画面被切掉）
- 现象：375px 视口下 `scrollW=781`，`gameCanvas` 右边缘到 781px，游戏画面右侧被裁。
- 根因：`canvas.style.width='800px'; canvas.style.height='600px'` 内联样式**优先级高于**响应式 CSS（`#game-wrapper{max-width:100vw}` + `canvas{width:100%}`），把 800×600 写死，窄屏溢出。
- 修复：删掉这两行内联样式，交由 CSS 响应式规则接管。输入坐标已通过 `getCanvasPos()` 的 `scaleX=CSS_W/rect.width`（rect 为实时显示尺寸）换算，等比缩小后依然准确。校验：`node --check` 通过。

### 3. 修复 prism.html 移动端横向溢出
- 现象：375px 下 `#viewport-wrapper` 右边缘到 588px（被 flex 居中后溢出到右侧）。
- 根因：`#viewport-wrapper` 写死 `width:800px; height:450px; flex-shrink:0`；而内部 `#game-viewport` 用绝对定位 + JS `transform:scale()` 适配窗口，缩放只改**视觉**不改 layout box，于是外层 800px 盒子始终撑开导致溢出。
- 修复：`#viewport-wrapper` 改为 `width:100%; max-width:800px; aspect-ratio:16/9; margin:0 auto`（去掉 flex-shrink:0）；`#game-viewport canvas` 改 `width:100%; height:100%`。输入坐标 `getCanvasPos()` 同样按 `rect.width/VW` 实时换算，不受影响。

### 4. Meta / SEO / 可访问性打磨（7 处，低风险高收益）
- `theme-color` 补齐：`index.html`、`projects.html` 原先缺失（`#d4ab6a`，与全站游戏页统一，移动端浏览器状态栏配色更协调）。
- `description` 补齐：`games/memory.html`、`sonic.html`、`puzzle.html`、`gravity.html`、`prism.html` 原先缺 meta description，各补了一句贴合玩法的简体中文简介（利于搜索/分享预览）。

### 5. 复测结果（`/tmp/audit_all.mjs`）
- 运行时错误：**无**；移动端横向溢出(375px)：**无**；桌面横向溢出(1440px)：**无**。
- meta：所有页 lang=zh-CN ✓、desc ✓、theme ✓、favicon ✓（根 `favicon.ico` 已 200，浏览器自动解析，子页无需逐个加 link）。

### 6. 已知但**未改**（告知用户的可选后续，避免破坏现有设计）
