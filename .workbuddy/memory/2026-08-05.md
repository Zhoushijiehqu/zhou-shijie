## 下午：修复 GitHub Pages 部署问题

用户反馈 `https://zhoushijiehqu.github.io/zhou-shijie/planet.html` 部署后"出问题"。经无头浏览器实测：页面本身能正常渲染（canvas、FPS、角色均正常），唯一报错是 `/favicon.ico` 404，且该请求发生在**域名根** `/favicon.ico`，不在 `/zhou-shijie/` 子路径下。根因是浏览器默认会去根域名请求 favicon，而 `planet.html` 等 6 个页面没有显式 `<link rel="icon">`，导致 GitHub Pages 项目站点（带 `/zhou-shijie/` 路径）出现根 favicon 404。

### 改动

1. **补显式 favicon**（inline SVG，不依赖路径）：
   - `planet.html` → 🪐
   - `games/memory.html` → 🧠
   - `games/sonic.html` → 👂
   - `games/puzzle.html` → 🧩
   - `games/gravity.html` → 🚀
   - `games/prism.html` → 🌈
2. **`sw.js`**：将 `lab.html` 加入 `CORE_ASSETS` 预缓存清单，并将 `CACHE_VERSION` 从 `game-house-v2` 递增到 `game-house-v3`，确保重新部署后旧缓存被清理。

### 额外发现

- 部署版目前**未包含上午的改动**：`lab.html` 返回 404，`ProfileData.nav` 没有"实验室"，`planet.html` 也没有返回链接。说明 GitHub Pages 部署的是上午改动之前的版本，需重新 push + 部署。
- 全站所有资源路径均为相对路径，未发现 `/assets/...` 这类会在项目站点下失效的绝对路径。

### 给用户重新部署的建议

1. 确认本地已 commit 上午的 `lab.html`、`planet.html`、`data/profile.js` 和下午的 favicon、`sw.js` 改动。
2. push 到 `main`（或当前 GitHub Pages 源分支）。
3. 等待 GitHub Pages 构建完成（通常 1–3 分钟）。
4. 用无痕模式访问 `https://zhoushijiehqu.github.io/zhou-shijie/planet.html`，确认左上角出现"← 游戏小屋"返回链接，控制台不再报 `/favicon.ico` 404。
5. 如需强制刷新 Service Worker：在页面打开 DevTools → Application → Service Workers → Unregister，然后刷新。
